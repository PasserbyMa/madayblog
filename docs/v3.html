1. 프로젝트 개요 & 기술 스택

madayV3는 통신사 구독 관리 시스템을 모델로 한 Spring Boot 포트폴리오 프로젝트입니다. MySQL(v3db)과 MariaDB(practicedb) 두 데이터소스를 동시에 연결해 멀티 DB 환경을 구현하고, SQL 콘솔로 두 DB를 각각 조작할 수 있습니다.

MySQL — v3db (schema.sql, Spring Boot 자동 실행)

-- member 테이블
CREATE TABLE IF NOT EXISTS member (
    id         BIGINT AUTO_INCREMENT PRIMARY KEY,
    name       VARCHAR(50)  NOT NULL,
    email      VARCHAR(100),
    phone      VARCHAR(20),
    birth_date DATE,
    address    VARCHAR(200),
    status     VARCHAR(10)  DEFAULT 'ACTIVE',
    created_at DATETIME     DEFAULT NOW(),
    updated_at DATETIME     DEFAULT NOW()
);

-- plan 테이블 (data_gb, call_min 포함)
CREATE TABLE IF NOT EXISTS plan (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    plan_name   VARCHAR(50)  NOT NULL,
    monthly_fee INT          NOT NULL,
    data_gb     INT,
    call_min    INT,
    description VARCHAR(200)
);

-- subscription 테이블 (member/plan 외래키, CASCADE)
CREATE TABLE IF NOT EXISTS subscription (
    id         BIGINT AUTO_INCREMENT PRIMARY KEY,
    member_id  BIGINT  NOT NULL,
    plan_id    BIGINT  NOT NULL,
    start_date DATE    NOT NULL,
    end_date   DATE,
    status     VARCHAR(10) DEFAULT 'ACTIVE',
    created_at DATETIME    DEFAULT NOW(),
    FOREIGN KEY (member_id) REFERENCES member(id) ON DELETE CASCADE,
    FOREIGN KEY (plan_id)   REFERENCES plan(id)
);

4. 멀티 데이터소스 설정

핵심 원칙 — Spring Boot는 JdbcTemplate 빈이 하나라도 존재하면 JdbcTemplateAutoConfiguration을 건너뛴다 (@ConditionalOnMissingBean(JdbcOperations.class)). MariaDB용 mariaJdbcTemplate을 직접 등록하므로, MySQL용 Primary JdbcTemplate도 반드시 명시적으로 등록해야 한다.

PrimaryDataSourceConfig.java — MySQL Primary

@Configuration
public class PrimaryDataSourceConfig {

    @Primary @Bean
    @ConfigurationProperties("spring.datasource")
    public DataSourceProperties dataSourceProperties() {
        return new DataSourceProperties();
    }

    @Primary @Bean
    public DataSource dataSource(DataSourceProperties properties) {
        return properties.initializeDataSourceBuilder().build();
    }

    // mariaJdbcTemplate 추가로 AutoConfiguration이 건너뛰므로 직접 등록
    @Primary @Bean
    public JdbcTemplate jdbcTemplate(DataSource dataSource) {
        return new JdbcTemplate(dataSource);
    }
}

MariaDbConfig.java — MariaDB 보조

@Configuration
public class MariaDbConfig {

    @Bean
    @ConfigurationProperties(prefix = "maria.datasource")
    public DataSource mariaDataSource() {
        return DataSourceBuilder.create().build();
    }

    @Bean
    public JdbcTemplate mariaJdbcTemplate(
            @Qualifier("mariaDataSource") DataSource dataSource) {
        return new JdbcTemplate(dataSource);
    }
}
주의: MariaDB 설정 키는 maria.datasource.jdbc-url (HikariCP 요구). url로 쓰면 HikariCP가 인식 못하고 부트 기동 시 "jdbcUrl is required with driverClassName" 오류 발생.

10. MemberService

수정 후: @Autowired 제거, @RequiredArgsConstructor + final 생성자 주입 적용.

@Service
@RequiredArgsConstructor
public class MemberService {

    private final MemberMapper memberMapper;

    public List<MemberDto> getPage(int page, int size, String keyword) {
        int offset = (page - 1) * size;
        return memberMapper.findPage(offset, size, keyword);
    }

    public int getTotalPages(int size, String keyword) {
        int total = memberMapper.count(keyword);
        return (int) Math.ceil((double) total / size);
    }

    public int getTotalCount(String keyword) { return memberMapper.count(keyword); }

    public MemberDto getById(Long id)    { return memberMapper.findById(id); }
    public void      create(MemberDto m) { memberMapper.insert(m); }
    public void      modify(MemberDto m) { memberMapper.update(m); }
    public void      remove(Long id)     { memberMapper.delete(id); }
}

11. MemberController

수정 후: @Controller (Thymeleaf 뷰 반환) + 일부 엔드포인트에 @ResponseBody (REST 혼용). URL prefix: /members.

@Controller
@RequestMapping("/members")
@RequiredArgsConstructor
public class MemberController {

    private final MemberService memberService;

    // GET /members?page=1&keyword= → 뷰: members/list
    @GetMapping
    public String list(@RequestParam(defaultValue = "1") int page,
                        @RequestParam(defaultValue = "")  String keyword,
                        Model model) {
        int size = 10;
        String kw = keyword.isBlank() ? null : keyword;
        model.addAttribute("members",     memberService.getPage(page, size, kw));
        model.addAttribute("currentPage", page);
        model.addAttribute("totalPages",  memberService.getTotalPages(size, kw));
        model.addAttribute("totalCount",  memberService.getTotalCount(kw));
        model.addAttribute("keyword",     keyword);
        return "members/list";
    }

    // GET /members/{id}/data → JSON (모달 상세 채우기용)
    @GetMapping("/{id}/data") @ResponseBody
    public MemberDto getData(@PathVariable Long id) {
        return memberService.getById(id);
    }

    // POST /members → JSON
    @PostMapping @ResponseBody
    public Map<String, Object> add(@RequestBody MemberDto member) {
        memberService.create(member);
        return Map.of("success", true, "message", "등록 완료");
    }

    // PUT /members/{id} → JSON
    @PutMapping("/{id}") @ResponseBody
    public Map<String, Object> edit(@PathVariable Long id,
                                     @RequestBody MemberDto member) {
        member.setId(id);
        memberService.modify(member);
        return Map.of("success", true, "message", "수정 완료");
    }

    // DELETE /members/{id} → JSON
    @DeleteMapping("/{id}") @ResponseBody
    public Map<String, Object> delete(@PathVariable Long id) {
        memberService.remove(id);
        return Map.of("success", true, "message", "삭제 완료");
    }
}

12. SubscriptionController

수정 후: @RequiredArgsConstructor 생성자 주입. Mapper를 직접 주입 (별도 Service 레이어 없음).

@Controller
@RequestMapping("/subscriptions")
@RequiredArgsConstructor
public class SubscriptionController {

    private final SubscriptionMapper subscriptionMapper;
    private final MemberMapper       memberMapper;   // 모달 셀렉트용 목록 제공
    private final PlanMapper         planMapper;

    // GET /subscriptions?page=1 → 뷰: subscriptions/list
    @GetMapping
    public String list(@RequestParam(defaultValue = "1") int page, Model model) {
        int size = 10, offset = (page - 1) * size;
        int total = subscriptionMapper.count();
        model.addAttribute("subscriptions", subscriptionMapper.findPage(offset, size));
        model.addAttribute("currentPage",   page);
        model.addAttribute("totalPages",    (int) Math.ceil((double) total / size));
        model.addAttribute("totalCount",    total);
        model.addAttribute("members",       memberMapper.findAll());
        model.addAttribute("plans",         planMapper.findAll());
        return "subscriptions/list";
    }

    @GetMapping("/{id}/data") @ResponseBody
    public SubscriptionDto getData(@PathVariable Long id) {
        return subscriptionMapper.findById(id);
    }

    @PostMapping @ResponseBody
    public Map<String, Object> add(@RequestBody SubscriptionDto sub) {
        subscriptionMapper.insert(sub);
        return Map.of("success", true, "message", "등록 완료");
    }

    @PutMapping("/{id}") @ResponseBody
    public Map<String, Object> edit(@PathVariable Long id,
                                      @RequestBody SubscriptionDto sub) {
        sub.setId(id);
        subscriptionMapper.update(sub);
        return Map.of("success", true, "message", "수정 완료");

    @DeleteMapping("/{id}") @ResponseBody
    public Map<String, Object> delete(@PathVariable Long id) {

}

16. SqlService & MariaSqlService

SqlService.java (수정 후 — Primary MySQL)

@Service
@RequiredArgsConstructor
public class SqlService {

    private final JdbcTemplate jdbcTemplate;  // @Primary 자동 주입 (MySQL)

    public Object execute(String sql) {
        String upper = sql.trim().toUpperCase();
        if (upper.startsWith("SELECT") || upper.startsWith("SHOW")
                || upper.startsWith("DESC")   || upper.startsWith("WITH")) {
            return jdbcTemplate.queryForList(sql);
        } else if (upper.startsWith("INSERT") || upper.startsWith("UPDATE")
                || upper.startsWith("DELETE")) {
            int rows = jdbcTemplate.update(sql);
            return Map.of("message", rows + "건 처리됨");
        } else {
            jdbcTemplate.execute(sql);
            return Map.of("message", "DDL 실행 완료");
        }
    }
}

MariaSqlService.java (MariaDB — @Qualifier 명시적 생성자, 기존 유지)

@Service
public class MariaSqlService {

    private final JdbcTemplate jdbcTemplate;

    // @Qualifier 때문에 Lombok @RequiredArgsConstructor 대신 명시적 생성자
    public MariaSqlService(@Qualifier("mariaJdbcTemplate") JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }

    public Object execute(String sql) {
        String upper = sql.trim().toUpperCase();
        if (upper.startsWith("SELECT") || upper.startsWith("SHOW")
                || upper.startsWith("DESC")   || upper.startsWith("WITH")) {
            return jdbcTemplate.queryForList(sql);
        } else if (upper.startsWith("INSERT") || upper.startsWith("UPDATE")
                || upper.startsWith("DELETE")) {
            int rows = jdbcTemplate.update(sql);
            return Map.of("message", rows + "건 처리됨");
        } else {
            jdbcTemplate.execute(sql);
            return Map.of("message", "DDL 실행 완료");
        }
    }
}
SQL 분기 표
SELECT / SHOW / DESC / WITH → queryForList() → List<Map> 반환 (표로 렌더링)
INSERT / UPDATE / DELETE → update() → {"message": "N건 처리됨"}
CREATE / DROP / ALTER 등 → execute() → {"message": "DDL 실행 완료"}

}

21. 주요 버그 & 해결 과정

① HikariCP jdbc-url 오류

오류: jdbcUrl is required with driverClassName
원인: MariaDB DataSource를 @ConfigurationProperties로 직접 바인딩할 때 HikariCP는 url이 아닌 jdbc-url 키를 요구한다.
해결: application.properties의 키를 maria.datasource.url → maria.datasource.jdbc-url로 변경.

② Primary JdbcTemplate 누락

오류: NoUniqueBeanDefinitionException 또는 SqlService가 mariaJdbcTemplate을 주입받아 MySQL 쿼리가 MariaDB로 날아가는 문제
원인: mariaJdbcTemplate 빈 등록 시 JdbcTemplateAutoConfiguration의 @ConditionalOnMissingBean(JdbcOperations.class) 조건이 이미 충족돼 MySQL용 JdbcTemplate 자동 생성을 건너뜀.
해결: PrimaryDataSourceConfig에서 @Primary @Bean JdbcTemplate jdbcTemplate()을 명시적으로 등록.

③ SHOW / DESC 쿼리 오류

오류: SHOW TABLES, DESC member 실행 시 "incorrect result size: expected 1, actual N" 예외
원인: SELECT 분기만 있던 초기 버전에서 SHOW/DESC가 else 분기(DDL execute)로 넘어가면 jdbcTemplate.execute()가 결과셋을 반환하지 않아 오류 발생.
해결: 조건을 SELECT || SHOW || DESC || WITH로 확장해 queryForList()로 처리.

④ Thymeleaf 3.1 + Spring Security 6 통합

상황: sec:authorize 태그가 Thymeleaf에서 인식되지 않음.
원인: Spring Boot 3.x는 Spring Security 6을 사용하므로 thymeleaf-extras-springsecurity5가 아닌 thymeleaf-extras-springsecurity6를 사용해야 한다.
해결: pom.xml에 org.thymeleaf.extras:thymeleaf-extras-springsecurity6 의존성 추가.

⑤ @Autowired 필드 주입 → 생성자 주입 전환

변경 대상 클래스: MemberController, MemberService, SubscriptionController, DashboardController, SqlController, MariaSqlController, SqlService

변경 방법:
  • 클래스 레벨에 @RequiredArgsConstructor 추가
  • @Autowired private XxxType xxx; → private final XxxType xxx;
효과:
  • final로 불변성 보장 및 null 불가
  • 단위 테스트 시 생성자로 직접 Mock 주입 가능
  • 순환 의존성 컴파일 타임 감지
  • Spring 공식 권장 방식 준수
예외: MariaSqlService는 @Qualifier("mariaJdbcTemplate")를 생성자 파라미터에 붙여야 해서 Lombok 대신 명시적 생성자 유지.

⑥ MariaDB 환경변수 MYSQL_* vs MARIADB_*

상황: MariaDB 10.x까지는 MYSQL_* 환경변수도 동작했으나, MariaDB 11에서는 MARIADB_* 사용을 권장하며 일부 MYSQL_* 키가 동작하지 않을 수 있음.
해결: docker-compose.yml에서 MariaDB 컨테이너 환경변수를 MARIADB_ROOT_PASSWORD, MARIADB_DATABASE, MARIADB_USER, MARIADB_PASSWORD로 명시.
