1. 전체 아키텍처 개요

이 블로그는 단순한 정적 사이트가 아니라, 실제 서버에서 돌아가는 풀스택 서비스다. Oracle Cloud (OCI) 위에 Docker Compose로 여러 컨테이너가 같이 실행되고, 서로 HTTP/네트워크로 통신한다.

인터넷 │ ▼ 포트 80/443 ┌─────────────────────────────────────┐ │ mablog_proxy (Nginx) │ ← 리버스 프록시, HTTPS 종료 │ - HTTPS 인증서 (Let's Encrypt) │ │ - /api/* → Next.js로 전달 │ └──────────────┬──────────────────────┘ │ 내부 네트워크 (mablog_network) ▼ 포트 8080 ┌─────────────────────────────────────┐ │ mablog_nextjs (Next.js 14) │ ← 웹앱 + API 서버 │ - 페이지 렌더링 (RSC) │ │ - REST API (/api/controller/...) │ │ - 시스템 API (/api/system/...) │ └──────┬──────────────────────────────┘ │ ├──────▶ mablog_mongodb (MongoDB 7) │ 데이터 저장 (포스트, 스택, 라즈베리파이 상태) │ ├──────▶ mablog_elasticsearch (ES 8.13) │ nginx 로그 검색/저장 │ └──────▶ docker.sock 실행 중인 컨테이너 목록 조회 nginx 로그 파이프라인: mablog_proxy (nginx) → access.log → 볼륨 공유 │ ▼ mablog_logstash (grok 파싱) │ ┌─────────────┴──────────────┐ ▼ ▼ mablog_kafka mablog_elasticsearch (topic: nginx-logs) (index: nginx-logs-날짜) │ mablog_kibana (시각화 UI) ← SSH 터널로만 접근 외부 연동: - GitHub API: 최신 커밋 조회 - Raspberry Pi: 주기적으로 상태 POST → MongoDB 저장 - Let's Encrypt (certbot): HTTPS 인증서 자동 갱신

핵심 개념: 왜 Docker를 쓰나?

Docker가 없으면 서버에 Node.js, MongoDB, Nginx, Java(Kafka/ELK) 등을 직접 설치해야 한다. 버전 충돌, 설정 꼬임 등 문제가 생긴다. Docker는 각 서비스를 격리된 컨테이너(독립 환경)로 실행하기 때문에 서로 영향을 주지 않는다. docker-compose.yml 파일 하나로 전체 인프라를 정의하고, docker-compose up -d 한 줄로 전부 실행된다.

3-2. 주요 키워드 설명

volumes (볼륨)

컨테이너는 종료하면 내부 데이터가 사라진다. 볼륨을 쓰면 호스트 디렉토리와 컨테이너 디렉토리를 연결해서 데이터를 영구 보존한다.

volumes:
  - ./mongo_data:/data/db    # 호스트의 ./mongo_data ↔ 컨테이너의 /data/db
  - ./nginx_logs:/var/log/nginx  # nginx 로그를 logstash가 같이 읽을 수 있게

핵심: nginx 컨테이너와 logstash 컨테이너가 ./nginx_logs를 공유 폴더처럼 사용한다. nginx가 access.log를 쓰면, logstash가 그 파일을 읽는다.

expose vs ports

expose: ['8080']    # Docker 내부 네트워크에서만 접근 가능 (외부 차단)
ports: ['80:80']    # 호스트의 80번 포트를 컨테이너의 80번 포트에 연결 (외부 접근 가능)
ports: ['127.0.0.1:27017:27017']  # 로컬호스트에서만 접근 가능 (외부 차단)

networks - aliases

mablog_elasticsearch:
  networks:
    mablog_network:
      aliases:
        - elasticsearch   # 언더스코어 없는 별명

컨테이너 이름 mablog_elasticsearch에는 언더스코어(_)가 있는데, URI 표준(RFC 3986)에서 언더스코어는 호스트명에 허용되지 않는다. 그래서 Logstash가 http://mablog_elasticsearch:9200으로 접속하면 파싱 오류가 난다. elasticsearch라는 별명(alias)을 붙여서 해결했다.

depends_on

서비스 시작 순서를 정한다. mablog_logstash는 mablog_kafka와 mablog_elasticsearch가 먼저 시작된 후에 시작된다. 단, "실행 시작"을 기다리는 것이지 "완전히 준비됨"을 보장하지는 않는다.

docker.sock 마운트

volumes:
  - /var/run/docker.sock:/var/run/docker.sock

Docker 소켓 파일. 이걸 컨테이너에 마운트하면, 컨테이너 안에서 호스트의 Docker를 제어할 수 있다. Next.js 컨테이너가 docker ps를 실행해서 실행 중인 컨테이너 목록을 가져오는 데 쓴다.

KAFKA_HEAP_OPTS / ES_JAVA_OPTS

KAFKA_HEAP_OPTS=-Xms256m -Xmx256m   # JVM 최소/최대 힙 256MB
ES_JAVA_OPTS=-Xms512m -Xmx512m      # Elasticsearch JVM 힙 512MB

Kafka, Elasticsearch, Logstash는 모두 Java(JVM) 기반이다. 메모리를 제한하지 않으면 OCI 무료 서버(24GB RAM 있지만) 에서 과도하게 쓸 수 있어 제한을 둔다. -Xms는 초기 힙 크기, -Xmx는 최대 힙 크기.

3-3. Kafka KRaft 모드

기존 Kafka는 메타데이터를 관리하기 위해 ZooKeeper라는 별도 서비스가 필요했다. KRaft 모드는 ZooKeeper 없이 Kafka 자체가 메타데이터를 관리한다 (Raft 합의 알고리즘 사용).

KAFKA_PROCESS_ROLES=broker,controller   # 브로커 + 컨트롤러 역할 동시 수행
KAFKA_LISTENERS=PLAINTEXT://:9092,CONTROLLER://:9093
# 9092: 메시지 produce/consume 포트
# 9093: 클러스터 내부 컨트롤러 통신 포트

4. 데이터베이스 — MongoDB

4-1. MongoDB란?

관계형 DB(MySQL, PostgreSQL)와 달리 문서(Document) 기반 NoSQL. 데이터를 JSON처럼 생긴 BSON 형식으로 저장한다. 테이블 대신 컬렉션(Collection), 행 대신 문서(Document).

RDB vs MongoDB 비교
RDB: Database → Table → Row → Column
MongoDB: Database → Collection → Document → Field

4-2. ConnectMongoDB.ts — 싱글톤 연결

let cached = (globalThis as CustomGlobalThis).mongooseCache;
if (!cached) cached = (globalThis as CustomGlobalThis).mongooseCache = {};

export const ConnectMongoDB = async () => {
  if (cached.conn && cached.conn.connection.readyState === 1) return cached.conn; // 이미 연결됨
  if (cached.promise) return cached.promise; // 연결 중

  cached.promise = mongoose.connect(MONGO_URI, opts); // 새 연결
  cached.conn = await cached.promise;
  return cached.conn;
};

왜 싱글톤인가? Next.js는 서버리스 환경에서 API 요청마다 코드가 실행된다. 매번 새 DB 연결을 만들면 연결이 수백 개가 생긴다. globalThis(전역 객체)에 연결을 캐싱해서 재사용한다. readyState === 1이면 이미 연결된 상태다.

중요 옵션: authSource: 'admin' — MongoDB 인증을 'admin' 데이터베이스에서 확인하도록 지정. docker-compose.yml에서 MONGO_INITDB_ROOT_USERNAME/PASSWORD로 설정한 계정이 admin DB에 만들어지기 때문.

4-3. 스키마 정의 (Mongoose)

Mongoose는 MongoDB를 Node.js에서 편리하게 쓰는 ODM(Object Document Mapper) 라이브러리. 스키마로 데이터 구조와 제약을 정의한다.

Posts 스키마

const postsSchema = new Schema({
  title:    { type: String, required: true, trim: true }, // 필수, 앞뒤 공백 제거
  content:  { type: String, required: true },             // 마크다운 원문
  category: { type: String, required: true },
  date:     { type: Date, default: Date.now },            // 없으면 현재 시각
  slug:     { type: String, required: true, unique: true }, // 중복 불가 (URL용)
}, { versionKey: false });  // __v 필드 제거

slug: URL에 쓰이는 식별자. 예를 들어 포스트 URL이 /post/elk-pipeline-study면 slug는 elk-pipeline-study다. unique: true로 중복 방지.

TypeScript 타입 계층

BaseInsertPostType              // title, content, category, date, slug
  └─ IPostData                  // + _id (MongoDB ObjectId)
       └─ IPostDataWithHtml     // + contentHtml (마크다운 → HTML 변환본)

MongoDB Aggregation (카테고리 통계)

await ModelPostsSetting.aggregate([
  { $group: { _id: '$category', count: { $sum: 1 } } }, // 카테고리별 그룹
  { $sort: { count: -1 } },                              // 많은 순 정렬
]);

SQL의 GROUP BY category ORDER BY count DESC와 동일. Aggregation Pipeline은 데이터를 단계별로 처리한다. CATEGORY_FILTER 위젯에서 사용.

5-2. apiClient.ts — 클라이언트 fetch 래퍼

각 API를 직접 fetch로 호출하면 URL, 헤더, 에러 처리를 매번 반복해야 한다. apiClient.ts에 모아서 함수 하나로 호출한다.

const jsonPost = (body: unknown): RequestInit => ({
  method: 'POST',

5-4. 서버 상태 API — /proc/stat 직접 읽기

function ReadCPU() {
  const stat = fs.readFileSync('/proc/stat', 'utf8');
  const line = stat.split('\n')[0]; // "cpu  3357 0 4313 1234567 ..."
  const fields = line.split(/\s+/).slice(1).map(Number);
  const idle  = fields[3];          // 4번째 값이 idle 시간
  const total = fields.reduce((a, b) => a + b, 0); // 전체 합
  return { idle, total };
}

/proc/stat는 리눅스 커널이 제공하는 가상 파일. CPU 사용 시간을 클럭 틱(clock tick) 단위로 기록한다. 두 번 읽어서 차이(delta)를 계산하면 그 사이의 CPU 사용률이 나온다.

CPU 사용률 = (1 - idle delta / total delta) × 100

5-5. Docker API — SSE (Server-Sent Events)

일반 REST API는 클라이언트가 요청해야 데이터를 받는다. SSE는 서버가 연결을 유지하면서 계속 데이터를 push한다. Docker 컨테이너 상태처럼 실시간 업데이트에 적합하다.

// 서버 (route.ts)
const stream = new ReadableStream({
  async start(controller) {
    const send = async () => {
      const containers = await getContainers();
      controller.enqueue(encoder.encode(`data: ${JSON.stringify(containers)}\n\n`));
      // SSE 형식: "data: JSON\n\n" — 빈 줄 두 개가 메시지 구분자
    };
    await send();                          // 연결 즉시 첫 전송
    const interval = setInterval(send, 5000); // 5초마다 반복
    request.signal.addEventListener('abort', () => {
      clearInterval(interval); controller.close(); // 클라이언트 끊으면 정리
    });
  },
});
return new Response(stream, {
  headers: { 'Content-Type': 'text/event-stream', 'Cache-Control': 'no-cache' },
});

// 클라이언트 (getDockerState.tsx)
const es = new EventSource('/api/system/docker');

  setContainers(JSON.parse(e.data));
};

6-3. 타이밍 공격 방어 (API Key 비교)

// 일반 비교 (취약)
if (provided === apiKey) ...   // 틀린 글자 위치에 따라 응답 시간이 다름

// 상수 시간 비교 (XOR)
let diff = 0;
for (let i = 0; i < apiKey.length; i++) {
  diff |= provided.charCodeAt(i) ^ apiKey.charCodeAt(i);
}
return diff === 0;
// XOR: 같으면 0, 다르면 1 → 모든 글자를 끝까지 비교 → 시간이 일정

타이밍 공격(Timing Attack): 응답 시간의 미세한 차이로 비밀키를 유추하는 공격. ===로 비교하면 앞 글자가 맞을수록 더 오래 걸린다. XOR 비교는 항상 같은 시간이 걸려 공격을 방어한다.

7-3. Logstash Grok 파싱

Grok은 정규식에 이름을 붙인 패턴이다. 텍스트 한 줄을 여러 필드로 분해한다.

grok {
  match => {
    "message" => "%{IPORHOST:client_ip} - %{DATA:user} \[%{HTTPDATE:log_timestamp}\] \"%{WORD:method} %{DATA:path} HTTP/%{NUMBER:http_version}\" %{NUMBER:status:int} %{NUMBER:bytes:int} \"%{DATA:referer}\" \"%{DATA:user_agent}\" RT=%{NUMBER:response_time:float}"
  }
}

패턴 설명:

패턴의미결과 필드
%{IPORHOST:client_ip}IP 또는 호스트명client_ip: "172.18.0.1"
%{HTTPDATE:log_timestamp}HTTP 날짜 형식log_timestamp: "05/Apr/2026:23:14:29 +0000"
%{WORD:method}공백 없는 단어method: "GET"
%{NUMBER:status:int}숫자 → 정수형status: 200
%{NUMBER:response_time:float}숫자 → 실수형response_time: 0.011

Kafka는 분산 메시지 큐(Message Queue)다. 데이터를 토픽(Topic)에 쌓으면, 여러 소비자(Consumer)가 나중에 가져갈 수 있다. 실시간 데이터 스트리밍에 쓴다.

지금 이 프로젝트에서 Kafka의 역할:
Logstash가 nginx 로그를 Elasticsearch와 Kafka 양쪽에 동시 전송한다. Kafka에는 nginx-logs 토픽에 쌓인다. 지금은 Kafka에서 데이터를 가져가는 Consumer가 없지만, 나중에 실시간 알림, 통계 집계 등을 붙일 수 있다.

9-3. 검색 Debounce

const [searchInput, setSearchInput] = useState('');  // 입력창 값
const [searchQuery, setSearchQuery] = useState('');  // 실제 검색에 쓰는 값

useEffect(() => {

단기 학습 목표 (1-2개월)

  1. MongoDB Aggregation 심화
    • $lookup (JOIN), $unwind, $project
    • 실습: 카테고리별 월간 포스트 수 집계
  2. Docker 심화
